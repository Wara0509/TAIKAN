# アーキテクチャ設計（STEP1）

## 1. モード構成

### ① 即決モード（ホーム）
- 最少入力で現在状況を表示
- 戦略を最優先で提示

### ② 精密モード（詳細入力）
- 3ステップのボタン選択（CLIでは番号選択）
  1. 環境（橋、風、吹き抜け、高所、日陰/日向、室内）
  2. 移動（徒歩多、自転車、ほぼ動かない）
  3. 時間変化（朝寒い、昼暑い、夕方寒い）

### ③ 結果画面
- 戦略（組み合わせ）
- 体感分布（例: 橋/外/室内）
- 状態（最低/最高/差分）
- 行動指針
- NG例
- 服装イメージ（初期はテキスト）

## 2. レイヤ分離

- `ui_cli.c`: 入力・表示
- `logic.c`: 計算・判定（純粋ロジック）
- `model.h`: データ構造の共通定義

これにより、GUI化しても `logic.c` を変更せず流用しやすい。

## 3. データモデル（概要）

- `WeatherInput`: 地域、日付、天気、気温、風速
- `BehaviorInput`: 環境/移動/時間変化
- `Distribution`: 各シーン体感、min/max/diff
- `StrategyResult`: メイン戦略、サブ戦略群、行動指針、NG例

## 4. ロジック概要

体感温度:

`体感温度 = 基本気温 - 風補正 - 場所補正 ± 日差し補正 ± 活動補正`

判定:
- `diff < 3` なら安定
- `diff >= 6` なら調整前提
- 風強い: 防風対策
- `min < 13`: 寒さリスク
- `max > 24`: 暑さリスク
- 活動多: 軽装推奨

## 5. CLIからGUIへの移行戦略

- STEP2-4で `logic.c` を完成
- STEP5でGUI（例: GTK, raylib+Nuklear, Dear ImGui）比較
- STEP6で最小GUIを追加
